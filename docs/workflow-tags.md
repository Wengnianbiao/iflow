# 工作流分类标签

工作流定义使用可选的 `tags` 字符串数组分类，例如：

```json
{
  "route": "report/query",
  "name": "报告查询",
  "version": 1,
  "tags": ["HIS", "门诊"],
  "tasks": []
}
```

标签随整份定义存入现有 `meta_workflow_def.json_data`，不需要新增表或数据库迁移。
复制工作流、复制 JSON 源码、下载和导入定义都会携带标签。标签属于对应的
`route + version`；复制定义创建新版本时继承标签，修改某一版本的标签不会同步修改历史版本。
没有 `tags` 或值为 `null` 的旧定义按无标签处理。保存时去除标签首尾空白、空名称和重复名称，
名称区分大小写，标签不参与路由解析和工作流执行。

配置列表提供标签列和“编辑标签”操作，定义编辑器的“工作流信息”也可以维护标签。
允许输入新名称，已有名称从全部最新工作流定义中汇总，不维护独立标签字典。

“标签筛选”下拉框同样汇总全部最新工作流定义的标签，可多选，命中任意一个所选标签即显示。
关键词搜索与标签筛选同时生效，搜索也覆盖标签名称；无标签的定义在未选择标签时仍会显示。
筛选条件保存在 URL 的重复 `tag` 参数中，改变筛选会回到第一页。

独立标签编辑调用 `PUT /api/workflow/metadata/tags?route=report/query&version=1`，
请求体为 `["HIS", "门诊"]`，清空传 `[]`。
接口仅更新对应版本 JSON 的 `tags`，返回标准 `ResultData<WorkflowDef>`；目标不存在时不会创建定义。
